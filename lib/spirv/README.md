# tairix-spirv

Stability tier: **experimental**

SPIR-V shader modules (`plans/SHADER.md` SH1, SH2, SH8): the checked model the
builder and the GPU backends share, its decoder, its validator, the lowering
view backends read an admitted module through, and its encoder.

## What it provides

- `Module::decode` — a module in either byte order, refused naming the word at
  fault, or a `Module` whose every instruction the grammar recognises and every
  operand it checked: ids nonzero, below the bound and defined once,
  enumerants known with their parameters, strings terminated UTF-8, a
  constant's or switch case's literal as wide as its numeric type, and every
  extended instruction an instruction of an imported `GLSL.std.450`.
- `Module` — the instructions, their typed operands (`Operand`, `Kind`,
  `Value`), each id's defining instruction, and the module's bytes in
  little-endian order.
- `Builder` — a module written from Rust: its sections laid out in SPIR-V's
  order, types and constants interned, functions written a block at a time
  through `if_then`, `if_else` and `while_loop`, and `finish` answering it
  only as the validator admits it; `GlslStd450` names each extended
  instruction. `lib/shaders`' pinned set is written through it.
- `Admitted::new` — the validator: a module refused naming the word at fault
  and the `Rule` broken, or admitted with the capabilities a device must
  support and each `EntryPoint`'s stage, workgroup size, bindings, push
  constants, stage interface and the module-scope variables it names;
  `EntryPoint::agree` decides a pipeline layout against them, the stages that
  may see each binding included. `Admitted::held_bytes` states the host memory
  an admitted module keeps.
- The lowering view — an admitted module's resolved types (`TypeId`, `Type`,
  `Member` with its explicit layout) and decorations, and `specialize`: every
  constant evaluated, total over every bit pattern, once a pipeline's
  `SpecValue`s are known, with each entry point's final workgroup size.
- `Encoder` — instructions written out (`Arg`), ids issued densely, and an
  existing module rewritten instruction by instruction (`rewriting`, `copy`).
  It frames and packs only: what it writes is decoded before anything relies on
  it.
- `assemble` (feature `test-support`, test scaffolding no build enables) —
  SPIR-V assembly text to a module, each operand read as the kind its position
  takes, so consumers' tests write shaders as text.

## Design notes

- Total and bounded: no input panics the decoder or the validator; a module
  past `MAX_MODULE_BYTES` or `MAX_INSTRUCTIONS`, or past one of the
  validator's fixed bounds (`MAX_*`), is refused. The decoder's memory follows
  the input's length, never a value it chose — ids are resolved through a
  sorted table of what the module defines, not a table sized by its bound —
  and every validator allocation fails closed.
- `src/tables.rs` is generated by `cargo xtask spirv --write` from the Khronos
  grammar vendored byte-identical in `assets/` (MIT; see `assets/LICENSE`) and
  checked for drift by `ci`. It recognises the core and the Khronos
  multi-vendor (KHR, EXT) extensions; provisional entries, single-vendor ones,
  and those reachable only through unrecognised capabilities are refused. It
  carries each instruction's and enumerant's gate, which the validator applies
  against the allow-lists in `src/validate/allow.rs`.
- No `unsafe`.

## Tests

The decoder's tests build modules through the encoder, which judges nothing, so
every refusal is exercised from a module that is otherwise valid. The
validator's tests assemble modules from text: shaders of each stage admitted,
each rule broken in a module otherwise admitted, and each bound reached and
passed. `tests/fuzz_spirv.rs` mutates valid modules and holds both total, their
refusals within the module, every accepted module to an exact re-encoding,
every admitted entry point to agreement with its own layout, and every admitted
module to a deterministic specialization.
