# `tairix-cp437`

IBM code page 437, the IBM PC's character set, and Unicode. The archive driver
reads and writes zip member names in it, and the PC emulator copies its text
screens and types pasted text through it, so the table has one definition.

A byte reads two ways. As **text**, the bytes below `80h` are ASCII with its
controls, the way a zip member's name or a DOS file's name spells them. As the
**glyph** a PC's screen draws, `01h`–`1Fh` and `7Fh` are the faces, arrows and
card suits of IBM's character generator, and `00h` draws nothing. The upper
half, `80h`–`FFh`, is the same either way: Unicode's published mapping
(`MAPPINGS/VENDORS/MICSFT/PC/CP437.TXT`).

| Item | What it is |
|---|---|
| `char_of(byte)` | The character `byte` spells as text. |
| `glyph_of(byte)` | The character `byte` draws; `00h` reads as a space. |
| `byte_of(ch)` | The byte that spells `ch` as text, if one does. |
| `glyph_byte_of(ch)` | The byte that draws `ch`, if one does; none for a control. |

The reverse table is sorted at compile time from the forward one and searched
by bisection. Tests take every byte through both readings and back, check
that no two bytes draw one character, and hold the table to Unicode's mapping
and the character generator's glyphs.
