# `tairix-spirv` — shader modules

`lib/spirv` is the one reading of a SPIR-V module in the tree
(`plans/SHADER.md`). The validator, the builder and the GPU backends share its
model, so they cannot disagree about what a module holds; a second parse
anywhere would be duplication.

A module is untrusted input: an application supplies it, and it may have
crossed a network. The decoder is the first parser between that input and the
GPU, so it is total, bounded and strict.

## Decoding

`Module::decode` takes a module's bytes in either byte order. It refuses one
with a `DecodeError` naming the word at fault and a `Fault`, or answers a
`Module` in which:

| Checked | Refused as |
|---|---|
| the bytes are whole words, at most `MAX_MODULE_BYTES`, with the SPIR-V magic number | `NotWords`, `TooLarge`, `Magic` |
| the version is 1.0 to 1.6, its reserved bytes clear; the reserved schema word is zero | `Version`, `Schema` |
| at most `MAX_INSTRUCTIONS` instructions, each of one or more words within the module | `TooManyInstructions`, `WordCount` |
| every opcode is one the grammar recognises | `UnknownOpcode` |
| each instruction's words hold exactly its operands | `MissingOperand`, `TrailingWords` |
| every id is nonzero and below the bound, and none is defined twice | `IdOutOfBound`, `DuplicateId` |
| every enumerated operand is a value its kind has, every bit of a bit set too, followed by the parameters each takes | `UnknownEnumerant` |
| every string is terminated, zero-padded to its word and UTF-8 | `BadString` |
| a constant's literal is as wide as its numeric result type, and a switch case's as its selector's integer type, each defined before it | `NumericWidth`, `Unresolved` |
| a nested operation (`OpSpecConstantOp`) is one whose operands are fixed in shape | `UnknownOpcode` |
| an import names `GLSL.std.450`, and an extended instruction an import, one of its instructions, and exactly its operands | `UnknownExtInstSet`, `UnknownExtInst`, `ExtInstArity` |

Nothing more is judged here. Whether the module's types agree, its control flow
is structured, its capabilities are admitted and its bindings match a pipeline
is the validator's to decide (`plans/SHADER.md` SH2).

The decoder is **total and bounded**: no input panics it, and what it allocates
follows the input's length, never a value the input chose. The first pass
frames each instruction and records each id it defines; the definitions are
sorted, so a second definition is found and every later lookup is a binary
search over what the module actually defines. A table sized by the module's
bound would let a few bytes declaring a bound of four billion claim gigabytes.

## The model

A `Module` holds its bytes in little-endian order, whatever order they arrived
in, and its `Instruction`s in order. Each instruction's `Operand`s carry their
grammar `Kind` and read as a `Value`:

| `Value` | Holds |
|---|---|
| `Id` | an id |
| `Word` | a one-word literal, an enumerant's value, an extended instruction's number, or an opcode |
| `Number` | a literal as wide as its context's type, one or two words, the low word first |
| `Text` | a string |

A grammar composite is two operands of their own kinds: an `OpPhi` pair is two
`IdRef`s, and a switch case a `LiteralContextDependentNumber` and an `IdRef`.
`Module::definition` answers the instruction defining an id, and
`Module::result` and `Module::result_type` an instruction's own.

## The grammar

`src/tables.rs` is generated by `cargo xtask spirv --write` from the Khronos
machine-readable grammars in `lib/spirv/assets/`, each byte-identical to its
SPIRV-Headers release (`vulkan-sdk-1.4.363.0`, SPIR-V 1.6 revision 7; MIT) and
pinned by SHA-256 in the generator. `cargo xtask spirv`, run by `ci`,
regenerates in memory and fails closed on drift; the build never touches the
network.

The grammar recognised is the core and what the Khronos multi-vendor extensions
add. An instruction or enumerant is left out — and a module using it refused as
unrecognised — when it is provisional, when only a single vendor's extension
enables it, or when every capability it names is itself unrecognised; the
capabilities are closed over first, each recognised only if reachable from the
core through recognised ones. That keeps 476 of the grammar's 877
instructions. The one extended instruction set recognised is `GLSL.std.450`.

The generator refuses a grammar whose shape the decoder does not read: a
required operand after an optional one, a repeated operand that is not last, a
result placed anywhere but first, an operand kind of an unknown category, a
quantified enumerant parameter, or a bit-set value of more than one bit.

## Encoding

`Encoder` writes instructions: `next_id` issues ids densely, `emit` writes an
opcode and its `Arg`s (ids, one- and two-word literals, strings terminated and
padded), and `finish` answers the module with its bound. `Encoder::rewriting`
starts from an existing module's version, generator and bound, and `copy` writes
one of its instructions as it stands, so a module re-encodes to exactly its
bytes.

The encoder frames and packs only: it refuses an id it did not issue, a string
holding a nul, an instruction past its word count, and a module past
`MAX_MODULE_BYTES`, but it does not check the grammar. What it writes is
decoded before anything relies on it, so there is one judge of what a module
may hold, and a builder's mistake is a refusal at build time.

## Tests

- The decoder's tests build a compute shader through the encoder using every
  shape the decoder reads — strings, enumerants with parameters, a bit set with
  one, constants of each width, a nested operation, an extended instruction,
  switches on 32- and 64-bit selectors — and replace one instruction at a time
  to exercise each refusal from a module that is otherwise valid.
- `tests/fuzz_spirv.rs` (in `cargo xtask fuzz`) mutates valid modules — bits,
  boundary words, insertions, deletions, duplications, truncations, either byte
  order — and holds the decoder total, its refusals within the module, and every
  accepted module to an exact re-encoding and an identical decode from either
  byte order.
- `cargo xtask miri` interprets the crate's tests and harness. The crate
  forbids `unsafe`; loom has nothing to model, since nothing here is shared
  between threads.
