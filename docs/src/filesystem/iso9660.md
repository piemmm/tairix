# ISO 9660 driver

`drivers/filesystem/iso9660` (`tairix-drv-fs-iso9660`) mounts CD and DVD
volumes read-only behind any `tairix_abi::driver::block::Block` device,
through `FilesystemRead`, `FilesystemSecurity`, `FilesystemAttrs` and
`FilesystemStats`. Every `FilesystemWrite` call is refused with `ReadOnly`.
It is served from user space ([Volumes served from user space](./served.md)): its `Run` binary binds
`tairix,volume-iso9660`, runs with `CAP_FS_SERVE` and `CAP_LOG_EMIT`, and
offers every disc read-only, so it is mounted so.

## Which tree is mounted

A disc can record several trees over the same files. Recognition is shared
with the volume probe (`lib/fsprobe`'s `iso9660::identify`), so both pick the
same one, read from the descriptor set of the disc's **last session** (the
session start the drive reports through `Block::disc_layout`):

1. the primary tree, when its root carries Rock Ridge (a SUSP `SP` entry) or
   its first records carry RISC OS `ARCHIMEDES` fields — those trees keep
   more than any other;
2. else the Joliet tree (the supplementary descriptor with a level 1–3
   escape), for its Unicode names;
3. else the ISO 9660:1999 enhanced tree;
4. else the primary tree.

High Sierra discs, ISO 9660's 1986 predecessor with its fields placed
apart, are read in their own layout.

## Names

- **Rock Ridge** (`NM`) names are POSIX names, matched exactly.
- **Joliet** names are UCS-2, listed as UTF-8.
- Every other tree's names are read as UTF-8, without a file's `;version`
  and an empty extension's `.`, and matched ASCII case-insensitively, as the
  systems that write them do.
- A RISC OS name whose `ARCHIMEDES` attributes carry `0x100` lists with its
  leading `_` as the `!` it stands for.
- A name no path could hold lists under an alias: a `/`, a NUL, or a unit
  that is no character becomes `_`, and a name so changed, one that is
  empty, `.` or `..`, or one longer than `FS_NAME_MAX` bytes is listed as
  much of it as fits, then `~` and the CRC-32 of the whole identifier — so a
  disc can name no traversal, and one alias names one record.
- Older versions of a file and associated files are not listed.

## Node ids and parents

A node's id is the place of its directory record, the root's that of its
`.` record; it is also the number `stat` reports. A directory's parent is
the directory its `..` record names, and its id is that of the parent's
record among the entries of the directory the parent's own `..` names. A
directory Rock Ridge relocated has `rr_moved` as its `..`; the `PL` entry
there names the directory it belongs in, so it climbs to that rather than to
`rr_moved`. A finished disc needs no record of a hold: `pin` checks the node
is live and answers its own id, `unpin` answers `Released`, and
`release_pins` has nothing to release.

## Contents

- **Multi-extent** files are assembled from up to 4096 records, wherever in
  their directory those run.
- **Interleaved** files are read unit by unit across their gaps.
- An **extended attribute record** ahead of a file's data is skipped, and its
  owner, group, permissions and dates are read.
- **zisofs** files (a Rock Ridge `ZF` entry) are inflated block by block;
  their listed size is the uncompressed one.
- Rock Ridge **symbolic links** (`SL`) read back as links, and relocated
  directories (`CL`/`RE`) appear where they belong.
- `fs_seek_region` reports every file as all data.
- A Rock Ridge **sparse file** (`SF`) lists with the size its entry
  records, but its layout is not read: its bytes and its regions are refused
  as unsupported, and one whose size does not decode is not listed.

## Times, owners and modes

Rock Ridge `TF` stamps come first, then the extended attribute record's
dates, then the recording date of the directory record. High Sierra's
six-byte date records no offset from UTC. Rock Ridge `PX` gives a node's
owner, group and mode; where there is none, an extended attribute record
its directory record flags as carrying them does; a node with neither
reports the ownerless default.

## Foreign metadata

What a disc records beside a file surfaces through the shared attribute keys
of the [metadata registry](./metadata-registry.md), so a copy onto ARXFS
keeps it:

| Record | Keys |
|---|---|
| RISC OS `ARCHIMEDES` field: load and execution words, attributes | `acorn.loadaddr`, `acorn.execaddr`, `acorn.attr`, and for a typed file `acorn.filetype` and `acorn.datestamp` |
| Apple's `AA` (and the original lengthless `BA`) entries, Technical Note FL36: HFS type, creator and Finder flags, or a ProDOS file type | `mac.type`, `mac.creator`, `mac.finderflags` |
| Amiga `AS` entries: protection bits and comment | `amiga.protection`, `amiga.comment` |

The values are exactly those ADFS presents, so a file copied from a RISC OS
disc, to ARXFS, and on to an ADFS volume keeps its native fields. A ProDOS
type is presented as type `p` + its type byte + its auxiliary type, creator
`pdos`. libisofs's `AA` entries (AAIP, not Apple's) are not read as Apple's.

## Bounds

Untrusted media is validated before use: continuation areas are followed at
most 16 deep and only within one sector, a record never runs past its sector
or its directory, and a lying length fails the read with `DeviceFault`
rather than being trusted. The fuzz harness
(`tests/fuzz_iso9660_mount.rs`) mutates mastered discs carrying every
extension and `genisoimage`-written fixtures.

## Tests

The driver's tests mount discs mastered by the shared
`tests/integration/iso9660_image` fixture crate, written from the
specifications rather than from this driver, and four discs written by
`genisoimage`. The USB optical QEMU vertical
(`tairix-test-optical-qemu-aarch64`) mounts a RISC OS disc from an emulated
USB drive and copies it onto ARXFS with `cp`, checking every file's bytes
and `acorn.filetype` on both sides.
