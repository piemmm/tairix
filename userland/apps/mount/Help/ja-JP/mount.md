## NAME

mount — マウントされたファイルシステムを一覧するか、ディスクイメージまたはアーカイブをマウントする

## SYNOPSIS

`mount`

`mount [option...] image [target]`

`mount --list-held`

`mount --replay-held name`

`mount --discard-held name`

## DESCRIPTION

オペランドがなければ、マウントされたファイルシステムを、ボリューム
が見える場所ごとに `source on target type fstype (options)` の 1 行
で一覧します。このとき `-t` は、コンマ区切りの一覧が挙げた種別だけを
一覧します。`no` で始まる一覧は、挙げていない種別をすべて一覧します。

`image` オペランドがあれば、そのディスクイメージファイルが収めるボ
リュームをマウントします。対象は ISO 9660 または UDF の光ディスク
（`.iso`）、Acorn ADFS または AmigaDOS のフロッピー
（`.adf`、`.adl`、`.adm`、`.ads`）、AmigaDOS のハードディスクのパー
ティション（`.hdf`）、または FAT32 のボリュームのいずれかです。
イメージが何を収めているかはその内容から識別され、名前から判断され
ることは決してありません。ボリュームは自分専用として `/Storage/name`
にマウントされ、名前はボリュームのラベル、なければイメージのファイ
ル名から付けられます。ほかの誰もそれを開くことはできません。イメー
ジへの書き込みが自分に許され、その形式が書き込みに対応していれば読
み書き可能で、そうでなければ読み取り専用でマウントされ、読み取り専
用のときは `mount` が警告します。イメージからマウントしたボリューム
上のプログラムは、決して実行されません。

`target` が `/Storage/name` であれば、ボリュームをその名前でマウン
トします。それ以外の `target` は `/Users` 配下または `/Storage` 内の
ボリューム上にある自分の空のディレクトリで、そこにもボリュームが見
えるようになります。FAT32 または ADFS のボリューム上のディレクトリ
では、ボリュームを見せることはできません。

アーカイブも同じようにマウントでき、アーカイブに収められた項目がボリュー
ムのファイルとフォルダーになります。対象は zip（`.zip`）、無圧縮または
gzip か bzip2 で圧縮した tar（`.tar`、`.tar.gz`、`.tgz`、`.tar.bz2`）、
単一のファイルを gzip か bzip2 で圧縮したもの（`.gz`、`.bz2`）、RISC OS
の Spark または ArcFS のアーカイブ（`.spk`、`.arc`）、または RAR のアー
カイブ（`.rar`）のいずれかです。RISC OS のファイルタイプと属性は、各項目
とともに保持されます。変更はアーカイブファイルを置き換えることで保存され
るため、アーカイブが読み書き可能でマウントされるのは、そのファイルと、そ
れを含むフォルダーの両方への書き込みが自分に許されている場合だけで
す。RAR のアーカイブは常に読み取り専用でマウントされます。複数のボリュー
ムに分割されたアーカイブや、項目の名前が暗号化されたアーカイブはマウント
されず、暗号化された項目は読み取れません。

ボリュームは、`unmount` で切り離すか、ログインセッションが終わるま
でマウントされたままです。パーティション分割されたディスク、RAID
アレイを構成するディスクの 1 台、または記録された所有者が常に尊重
されるファイルシステム（ext2、ext3、ext4、ARXFS）を収めたイメージは
マウントされず、`mount` がその理由を示します。

まだ書き込まれていない変更を保持したまま挿し直されたディスクは、その
デバイスが同じディスクでありコピーではないことを示せない場合、変更を
保持したまま読み取り専用でマウントされます。一覧ではそのボリュームに
`[replay-unconfirmed]` が付き、`--list-held` はそうしたボリュームだけを
一覧表示します。`--replay-held` は、内容がそれ以降変わっていないことを
示していれば変更をそのディスクに書き込み、`--discard-held` は変更を
破棄してディスクを現状のまま受け入れます。どちらの場合もボリュームは
再びマウントされ、可能であれば読み書き可能になります。応答するには
マウント権限（`CAP_FS_MOUNT`）が必要です。取り外し可能なディスクに
ついては、デスクトップもコンピューターの前にいるユーザーに尋ねます。

## OPTIONS

- `-r, --read-only` — ボリュームを読み取り専用でマウントします
  （`-o ro` と同じ）。
- `-w, --rw, --read-write` — ボリュームを読み書き可能でマウントし、
  できなければマウントしません。イメージへの書き込みが自分に許されて
  いない場合や、そのファイルシステムが書き込みに対応していない場合は、
  マウントされません。後から指定した `-r` はこれを取り消しますが、
  後から指定した `-o ro` または `-o rw` は取り消しません。
  読み取り専用かどうかは、`-r`、`-w`、`-o ro`、`-o rw` のうち最後に
  指定したもので決まります。
- `-t, --types <list>` — ファイルシステムをコンマ区切りで、マウント
  一覧での名前（`iso9660`、`udf`、`adfs`、`affs`、`fat32`、`zip`、
  `tar`、`tar.gz`、`tar.bz2`、`gzip`、`bzip2`、`spark`、`arcfs`、`rar`）
  で指定し、イメージはそのいずれかを収めていなければなりません。何を収め
  ていてもよければ `auto` を指定します。`no` で始まる一覧は、イメージが
  収めていてはならないものを挙げます。イメージが何を収めているかはその内
  容から識別されるので、順序で選ばれるものはありません。UDF と ISO 9660
  の両方を収めた光ディスクは、その ISO 9660 が Rock Ridge または
  RISC OS のレコードを保持していない限り、UDF としてマウントされます。
  そのどれも収めていないイメージや、ディスクイメージが収める種別を一つ
  も挙げていない一覧の場合は、マウントされません。
- `-o, --options <list>` — `ro`、`rw`（可能な場合は読み書き可能で、
  既定）、`noexec`、`loop`、`name=name`（ボリュームに付ける名前）を
  コンマで区切った一覧。`noexec` と `loop` は、
  イメージのマウントには指定しなくても常に適用されます。
- `-v, --verbose` — ボリュームをどこにマウントしたかを表示します。
- `-l, --show-labels` — 一覧のために受け付けます。一覧に加えるラベル
  はありません。
- `--list-held` — `--replay-held` または `--discard-held` を待つ変更を
  保持しているボリュームだけを一覧表示します。
- `--replay-held <name>` — 内容がまだ変わっていないことを示していれば、
  ボリュームが保持している変更をそのディスクに書き込みます。`name` は
  `/Storage` 内のボリュームの名前、ボリュームが表示されている
  ディレクトリ、またはその `id::` ルートです。
- `--discard-held <name>` — ボリュームが保持している変更を破棄し、
  ディスクを現状のまま受け入れます。
- `-h, -?, --help` — このコマンド自身の短いヘルプを表示します。

## EXAMPLES

- `mount` — マウントされたファイルシステムを一覧する。
- `mount Workbench.adf` — Amiga のフロッピーイメージを、ラベルが
  その名前なら `/Storage/workbench` にマウントする。
- `mount -r disc.iso /Storage/disc` — 光ディスクのイメージを `disc`
  として読み取り専用でマウントする。
- `mount -v -t adfs Elite.adl` — Acorn のフロッピーイメージを
  マウントし、その場所を表示する。
- `mount Photos.zip` — zip アーカイブを、アーカイブとそのフォルダーへの
  書き込みが許されていれば読み書き可能でマウントする。
- `mount -r backup.tar.gz /Storage/backup` — 圧縮された tar を `backup`
  として読み取り専用でマウントする。
- `mount --list-held` — 変更が応答を待っているボリュームを一覧表示する。
- `mount --replay-held backup` — `/Storage/backup` が保持している変更を
  そのディスクに書き込む。

## EXIT STATUS

- `0` — 一覧を出力した、ボリュームをマウントした、または保持されて
  いた変更を書き込んだか破棄した（または短いヘルプを出力した）。
- `1` — コマンドラインを解釈できなかった、またはボリュームの変更に
  応答する権限がなかった。
- `2` — マウント一覧を読み取れなかった、または端末に
  書き込めなかった。
- `32` — イメージがマウントされなかった、またはボリュームの変更が
  書き込まれも破棄されもしなかった。

## ENVIRONMENT

- `LANG` — 短いヘルプに使う優先ロケール（`fr-FR` のような BCP-47
  タグ）。
