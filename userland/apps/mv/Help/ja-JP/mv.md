## NAME

mv — ファイルとディレクトリを移動（改名）する

## SYNOPSIS

`mv [-finvT] [-t dir] [--] source... dest`

## DESCRIPTION

各ソースオペランドを宛先へ移動します。ソースが一つで、宛先がディレクトリ
を指さない場合、ソースはその正確なパスへ改名されます。宛先が既存のディレ
クトリを指す場合 — そしてソースが複数あるときは常に — 各ソースはそのディ
レクトリの*中へ*、自身の基底名で移動されます。

同じボリューム内の移動は、ノードの同一性を保つ不可分な改名である。ボリュ
ームをまたぐ移動も同じ約束を守る。コピーを宛先の隣に組み立て、ディスクに
書き込み、一度の改名で所定の位置に置き、その後でのみソースを削除する。し
たがって移動が完了するまで宛先は元の内容を保ち、失敗やクラッシュがあって
も何も失われない。いずれの場合も、ディレクトリが置き換えるのは空のディレ
クトリだけであり、ディレクトリを置き換えられるのはディレクトリだけであり、
ディレクトリが自身の部分木の中へ移動することはない。

既存の宛先は既定では上書きされ、`-n` では飛ばされ、`-i` では標準エラース
トリーム上で尋ねられます（断られた質問はその移動をエラーなしで飛ばしま
す。読めない返答が同意として扱われることは決してありません）。最初の失敗
で、後続のオペランドに移る前に実行が止まります。`--` はオプション解析を
終え、以降のすべての引数はパスです。

コピーは、宛先が保持できる限り、各ファイルの穴、拡張属性（RISC OS のファ
イルタイプ、Mac のタイプとクリエーター）、パーミッションビットと所有者を
引き継ぎ、シンボリックリンクは指す先ではなく、同じターゲットを保持するリ
ンクとして移動する。移動する者が元の所有者に返せないファイルは、set-ID
ビットを外したうえで移動する者のものになる。タイムスタンプは引き継がない。
このシステムにはそれを設定する呼び出しがない。宛先が保持できない属性は、
ソースが完全に消える前に、実行終了時の一度の警告と、標準情報ストリーム上
の `omission` レコードで報告される。

## OPTIONS

- `-f, --force` — 上書き前に決して尋ねない。`-f`、`-i`、`-n` のうち最後
  に指定したものが優先する。
- `-i, --interactive` — 既存の宛先を上書きする前に尋ねる。`y`/`Y` で始ま
  る返答だけが同意。
- `-n, --no-clobber` — 既存の宛先を決して上書きしない。
- `-v, --verbose` — 各移動を `renamed 'source' -> 'dest'` として報告し、
  ボリュームをまたぐ移動は `copied 'source' -> 'dest'` に続けて
  `removed 'source'` として報告する。
- `-t dir, --target-directory=dir` — すべてのソースを `dir` へ移動する。
  `dir` は既存のディレクトリでなければならない。値は密着形
  （`-tdir`、`--target-directory=dir`）または次の引数として与える。
- `-T, --no-target-directory` — 宛先を普通のファイルとして扱う。許される
  ソースはちょうど一つ。`-t` とは組み合わせられない。
- `-h, -?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `mv draft.txt final.txt` — ファイルを一つ改名する。
- `mv -v a.txt b.txt Archive` — 両ファイルを `Archive` へ移動し、各移動
  を報告する。
- `mv -n new.cfg current.cfg` — 宛先がまだ存在しないときだけファイルを
  据え付ける。

## EXIT STATUS

- `0` — すべての移動が成功した（`-n` による飛ばしと断られた `-i` の質問
  は失敗ではない）。
- `1` — ファイルシステム・問いかけ・出力の失敗。理由は標準エラーに印字さ
  れる。
- `2` — コマンド行を解釈できなかった。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`ja-JP` のような BCP-47 タグ）。
