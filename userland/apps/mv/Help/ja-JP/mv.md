## NAME

mv — ファイルとディレクトリを移動（改名）する

## SYNOPSIS

`mv [-finvT] [-t dir] [--] source... dest`

## DESCRIPTION

各ソースオペランドを宛先へ移動します。ソースが一つで、宛先がディレクトリ
を指さない場合、ソースはその正確なパスへ改名されます。宛先が既存のディレ
クトリを指す場合 — そしてソースが複数あるときは常に — 各ソースはそのディ
レクトリの*中へ*、自身の基底名で移動されます。

同じボリューム内の移動は、ノードの同一性を保つ不可分な改名です。ボリュー
ムをまたぐ移動も同じ約束を守ります。コピーは宛先の隣に組み立てられ、完成
するまでは所有者だけが読めるようにされ、ディスクに書き込まれてから、一度
の改名で所定の位置に置かれます。複写したものが削除されるのはその後だけで
す。したがって移動が完了するまで宛先は元の内容を保ち、失敗やクラッシュが
あっても何も失われません。複写の間にソースへ追加されたファイルや変更され
たファイルは、それを含むディレクトリとともに元の場所に残され、報告されま
す。変更回数を記録しないボリュームや、時刻を粗くしか記録しないボリューム
（FAT の 2 秒）では、その粒度の内に行われた同じ長さの書き換えが見逃され
ることがあります。いずれの場合も、ディレクトリが置き換えるのは空のディレ
クトリだけで、ディレクトリ以外のものがディレクトリを置き換えることはな
く、ディレクトリが自身の部分木の中へ移動することもありません。

既存の宛先は既定では上書きされ、`-n` では残され（GNU と同じく
`not replacing` と表示し、実行を失敗とします）、`-i` では標準エラースト
リーム上で尋ねられます（断られた質問はその移動を飛ばし、実行を失敗としま
す。読めない返答が同意として扱われることは決してありません）。移動できな
いオペランドは報告され、それでも次のオペランドは移動されます。`--` はオ
プション解析を終え、以降のすべての引数はパスです。

コピーは、宛先が保持できる限り、各ファイルの穴、拡張属性（RISC OS のファ
イルタイプ、Mac のタイプとクリエーター）、パーミッションビットと所有者を
引き継ぎ、シンボリックリンクは指す先ではなく、同じターゲットを保持するリ
ンクとして移動します。別の所有者に返されたファイルは set-ID ビットなしで
届きます。所有者が変わるときにシステムがこれを消去するためです。移動する
者が返せないファイルは移動する者のものになり、移動する者がそのグループを
保持できる場合は元のグループのままとなり、保持されなかった所有者やグルー
プの set-ID ビットは外されます。タイムスタンプは引き継がれません。このシ
ステムにはそれを設定する呼び出しがありません。宛先が保持できない属性は、
ソースが完全に消える前に、実行終了時の一度の警告と、標準情報ストリーム上
の `omission` レコードで報告されます。

## OPTIONS

- `-f, --force` — 上書き前に決して尋ねない。`-f`、`-i`、`-n` のうち最後
  に指定したものが優先する。
- `-i, --interactive` — 既存の宛先を上書きする前に尋ねる。`y`/`Y` で始ま
  る返答だけが同意。
- `-n, --no-clobber` — 既存の宛先を決して上書きしない。残した宛先はそれ
  ぞれ `not replacing 'dest'` として報告する。
- `-v, --verbose` — 各移動を `renamed 'source' -> 'dest'` として報告し、
  ボリュームをまたぐ移動は GNU と同じくエントリーごとに報告する。各ディ
  レクトリは `created directory 'dest'`、それ以外はコピーするたびに
  `copied 'source' -> 'dest'` とし、続いてソースが消えるたびにそれぞれ
  `removed 'source'` または `removed directory 'source'` とする。
- `-t dir, --target-directory=dir` — すべてのソースを `dir` へ移動する。
  これは既存のディレクトリでなければならない。値は密着形
  （`-tdir`、`--target-directory=dir`）または次の引数として与える。
- `-T, --no-target-directory` — 宛先を普通のファイルとして扱う。許される
  ソースはちょうど一つ。`-t` とは組み合わせられない。
- `-h, -?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `mv draft.txt final.txt` — ファイルを一つ改名する。
- `mv -v a.txt b.txt Archive` — 両ファイルを `Archive` へ移動し、各移動
  を報告する。
- `mv -n new.cfg current.cfg` — 宛先がまだ存在しないときだけファイルを据
  え付ける（存在するなら `not replacing` と表示する）。

## EXIT STATUS

- `0` — すべての移動が成功した。
- `1` — 移動できないオペランドがあった、`-n` が宛先を残した、`-i` の質問
  が断られた、ソースの中の何かが移動中に変わったため残された、または問い
  かけか出力が失敗した。各失敗の理由は標準エラーに印字される。解釈できな
  かったコマンド行も `1` で終了する。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`ja-JP` のような BCP-47 タグ）。
