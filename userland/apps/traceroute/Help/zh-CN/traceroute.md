## NAME

traceroute — 打印回显探测到达网络主机所经过的路由

## SYNOPSIS

`traceroute [option...] host [packetlen]`

## DESCRIPTION

向主机发送 ICMP（IPv4）或 ICMPv6（IPv6）回显请求，
跳数限制每次增加一跳，并打印每个报告探测跳数限制耗尽的路由器，直到主机本身应答。
探测通过用户空间网络栈中打开的 ICMP 回显套接字发出，受 `CAP_NET` 和 `CAP_NET_RAW` 管控并经过审计。

目标是 IPv4 或 IPv6 地址字面量，或通过系统存根解析器解析的主机名；
字面量无需查询。

每一跳在其全部探测都有结果后单独打印一行：先是跳号，然后是每个探测的往返时间；
只要应答者与前一个探测不同，就在前面加上它的地址（未给出 `-n` 时还有名字）
。在等待时间内没有应答的探测打印为 `*`。报告路径无法继续的路由器会标记其探测——`!N` 网络不可达、
`!H` 主机不可达、`!P` 协议不可达、`!X` 被管理性禁止、
`!S` 源路由失败、`!F-mtu` 数据包过大、`!<code>` 其他——追踪在该跳停止。
主机应答或到达跳数上限时也会停止。

同时有多个探测在等待（`-N`），因此一连串沉默的跳只需一次等待，而不是每个探测一次；
但某一跳仍要等到它之前的每一跳都打印后才会打印。

探测是 ICMP 回显请求，即 `-I` 所选的方式；选择 UDP 或 TCP 探测的选项会被拒绝，
而不是被悄悄忽略。

## OPTIONS

- `-4` — 要求 IPv4 目标。
- `-6` — 要求 IPv6 目标。
- `-I, --icmp` — 使用 ICMP 回显探测（唯一的方式，也是默认）。
- `-f, --first` — 首批探测携带的跳数限制（默认 1）。
- `-m, --max-hops` — 探测的最高跳数限制（默认 30）。
- `-q, --queries` — 每跳发送的探测数（默认 3，最多 10）。
- `-N, --sim-queries` — 同时等待的探测数（默认 16，最多 64）。
- `-w, --wait` — 等待每个探测应答的秒数（可为小数，默认 5）。
- `-n` — 数字输出：只显示地址，不做反向解析。
- `-?, --help` — 显示本命令自己的简短帮助。

`packetlen` 是每个探测的总长度（字节），包括报头（IPv4 默认 60，
IPv6 默认 80）。

## EXAMPLES

- `traceroute example.com` — 追踪到主机的路由。
- `traceroute -n 192.0.2.1` — 数字输出，不查询名字。
- `traceroute -q 1 -w 1 -m 20 gateway` — 每跳一个快速探测，最多二十跳。
- `traceroute -6 host.example` — 通过 IPv6 追踪。

## EXIT STATUS

- `0` — 追踪已运行，无论是否到达主机（或已写出简短帮助）。
- `2` — 命令行无法理解、目标无法解析、套接字无法打开，或探测无法发送。

## ENVIRONMENT

- `LANG` — 简短帮助的首选区域设置（如 `fr-FR` 的 BCP-47 标签）。
