## NAME

ln — ファイル間のリンクを作成する

## SYNOPSIS

`ln [-srLPdFfinvT] [-t dir] [--] target... [link_name]`

## DESCRIPTION

各ターゲットを指すシンボリックリンクを作成します。オペランドが 1 つの
ときは、ターゲット自身の名前で作業ディレクトリにリンクを作ります。2 つ
のときは、2 番目がディレクトリ（あるいは `-n` を与えない限りディレクトリ
へのリンク）ならその中に作り、そうでなければそれがリンクの名前になります。
3 つ以上のときは、最後のオペランドがすでにディレクトリでなければなりません。

ターゲットは**そのまま**保存され、決して解決されません。相対でもよく、
`..` を含んでもよく、何も指していなくてもよいので、リンクは正当に宙ぶらりん
になり得ます。保存前に文法だけは検査されるため、どの解決器も辿れない
ターゲットは拒否されます。リンクの作成は、それが指すものに対する権限を
何も与えません。以降の利用はそのたびに、あなた自身の識別のもとで構成要素
ごとに認可されます。

リンク名がすでに使われている場合、`-f` または `-i` が置き換えを指示しない
限り拒否されます。置き換えの際、新しいリンクは作成されてから初めて、一度の
操作でその名前に取って代わります。そのため、作れないリンク（たとえばター
ゲットがない場合）は名前を元のまま残し、すでにそこにあるリンクを通ってその
指す先に作用することもありません。ディレクトリが置き換えられることはありま
せん。自分が指すファイルそのものに取って代わることになるリンクは、同一ファ
イルとして拒否されます。自身の名前へ強制的にリンクされるファイルと、リンク
自身のディレクトリから読んだターゲットが、置き換えることになるファイルその
ものであるシンボリックリンクがこれに当たります。GNU は代わりにそのターゲッ
トを作業ディレクトリから読み、`-i` で同意するとファイルをそれ自身へのリン
クで置き換えます。

作れないリンクは報告され、それでも次のリンクは作られます。`--` はオプショ
ン解析を終わらせ、以降の引数はすべてオペランドになります。

`-s` を付けない場合、リンクは**ハードリンク**です。ターゲット自身の inode
に対する二つ目のディレクトリエントリで、両方の名前が一つのファイルに達し、
一方への書き込みはもう一方からも見え、最後の名前が削除されるまでファイルの
記憶域は残ります。両方の名前は同一ボリューム上になければならず、ディレクトリ
に二つ目の名前が与えられることはありません。ファイルツリーが木のままである
ことこそが、`..` を「実際に通ってきたディレクトリ」たらしめています。

`-r` はシンボリックリンクのターゲットを、リンク自身のディレクトリから
の相対で格納します。両側はまずファイルシステムが正規化するので、その差
は厳密です。正規化された二つの経路は `..` もリンクも含みません。同じ計
算を書かれたままのオペランドに対して行えば、リンクが絡んだ途端に別の物
を指してしまいます。`-r` には `-s` が必要です。ハードリンクは相対にす
べきターゲットを格納しないからです。

`-b`/`-S` は呼び出すバックアップ機構が存在しないため拒否されます。

## OPTIONS

- `-s, --symbolic` — ハードリンクではなくシンボリックリンクを作成する。
- `-r, --relative` — 各シンボリックリンクのターゲットを、リンク自身の
  ディレクトリからの相対で格納する。`-s` が必要。
- `-L, --logical` — ターゲットがシンボリックリンクのとき、リンク自身では
  なくそれが指す先をハードリンクする。
- `-P, --physical` — 最終シンボリックリンクをたどらず、綴られたとおりの
  ターゲットをハードリンクする。既定。
- `-d, -F, --directory` — ディレクトリのオペランドを受け付ける。リンク
  自体は拒否される: ディレクトリに二つ目の名前を与えられる利用者はいない。
- `-f, --force` — 既存のリンク名を新しいリンクで置き換える。
- `-i, --interactive` — 既存のリンク名を置き換える前に確認する。`y`/`Y` で
  始まる返答のみが同意となり、断るとそのリンクは飛ばされ、実行は失敗とな
  る。`-f` と `-i` は後に指定した方が効く。
- `-n, --no-dereference` — ディレクトリへのシンボリックリンクである
  行き先を、リンクを作るディレクトリではなく、それが同時にそうである
  ただの名前として扱う。
- `-v, --verbose` — 作成した各リンクを、シンボリックリンクなら
  `'link' -> 'target'`、ハードリンクなら `'link' => 'target'` の形で報告す
  る。
- `-t dir, --target-directory=dir` — 各リンクを `dir` に作成する。`dir`
  はすでにディレクトリでなければならない。値は続けて（`-tdir`、
  `--target-directory=dir`）または次の引数として与える。
- `-T, --no-target-directory` — 行き先をリンク名として扱い、埋めるべき
  ディレクトリとしては扱わない。オペランドは正確に 2 つ。`-t` とは併用
  できない。
- `-h, -?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `ln -s /System/Commands/ls.app tools/ls` — 名前をバンドルにリンクする。
- `ln -s ../shared/notes.txt` — 相対ターゲットで `notes.txt` をここに
  リンクする。
- `ln -sv -t Links a.txt b.txt` — 両方のファイルを `Links` にリンクし、
  各リンクを報告する。
- `ln -sfn /Storage/media Music` — 既存の `Music` リンクを新しい
  ディレクトリに向け直す。中にリンクを作るのではなくリンク自体を
  置き換える。

## EXIT STATUS

- `0` — すべてのリンクが作成された（または短いヘルプが書き出された）。
- `1` — それ以外（`-i` を断った場合も含む）。理由があれば標準エラーに出
  る。理解できないコマンド行も `1` で終了する。

## ENVIRONMENT
