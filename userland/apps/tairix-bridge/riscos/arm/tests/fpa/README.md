# FPA conformance vectors

Generated by `cargo xtask riscos-fpa <module> --write-sample`; never edit
by hand.

Source: the answers of FPEmulator 4.39, run as an opaque program
on the emulator's own processor. The module file's
SHA-256:

    4b733398cee58a5958e13318bba3b335dbdf7e123026dc036e43e2866fa3200e

Each vector is an FPA instruction run natively by the processor: the
registers and memory the harness drew for it, the FPA state FPEmulator
read back once the drawn one was loaded, and what the processor left.
It is kept only where FPEmulator, given the same, left the same in
every register, every word of memory, the FPA's registers and FPSR,
and a trap's exception dump. Those answers are all it takes from
FPEmulator: no byte of the module is carried here.

The FPA rounds a transcendental value and a packed decimal conversion
correctly, which FPEmulator does not: such a case agrees, but is not
kept, where the two lie within FPEmulator's error. A case reading
what FPEmulator mishandles or the data sheet leaves undefined is not
held to FPEmulator; those that differed:

- transcendentals of unnormals or in the denormal range: 13
- remainders of uncommon operands: 9
- packed loads of digits above nine: 39

`fpemulator-vectors.bin` is the `tairix_riscos_arm::vectors` encoding of the first
agreeing cases of each class, drawn from seed `0x46504134` over 20000
cases, 8 of them skipped as PC-relative stores over the
instruction. Every other case agreed when the sample was written.
