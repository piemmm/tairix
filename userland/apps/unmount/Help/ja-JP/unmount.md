## NAME

unmount — マウント済みボリュームの切り離し

## SYNOPSIS

`unmount [option...] name`

## DESCRIPTION

`name` としてマウントされたボリュームを運用から外します。ファイル
システムとデバイスをフラッシュし、`/Storage` 配下のマウントを撤去
し、ボリュームの恒久的な `id::` ルートを取り下げます。`name` は
ボリュームのカタログ名（`usb1`）またはマウントポイントのパス
（`/Storage/usb1`）で、システム情報 API のマウント一覧と照合され
ます。

未確定の書き込みを残したままデバイスが抜かれたボリュームは、
`unavailable-dirty`（または `unavailable-lost`）としてマウント一覧
に残り、通常の `unmount` は拒否します。保持されたデータは検証付き
の再挿入のために保管されています。ファイルがまだ開かれているボリューム、
またはプログラムが作業ディレクトリとしているボリュームに対しても、通常の
`unmount` は拒否します。`--force` は意図的な出口です — ボリューム上でま
だ開かれているファイルは切断され、そこで作業しているプログラムはもう存在
しないディレクトリに取り残され、保持データは破棄されてボリュームは撤去さ
れ、手放したものは監査ログに記録されます。健全なボリュームに対する
`--force` は従来どおりクリーンにフラッシュして切り離します。クリーンな確
定が可能な限り、何も破棄されません。

切り離しにはマウント権限（`CAP_FS_MOUNT`）が必要です。カーネルが
これを検査し、すべての判断を監査します。恒久的なブートボリューム
とシステムのビュー結合は切り離せません。

## OPTIONS

- `-f, --force` — 強制アンマウント：ボリューム上でファイルが開かれている
  間も、プログラムがそこで作業している間も、未確定のデータを確定できない
  場合も、ボリュームを撤去し、開いているファイルを切断して保持データを破
  棄します。
- `-?, --help` — このコマンドの短いヘルプを表示します。

## EXAMPLES

- `unmount usb1` — `usb1` としてマウントされたボリュームをクリーン
  に切り離す。
- `unmount /Storage/usb1` — 同じ操作をマウントポイントで指定。
- `unmount --force usb1` — 利用不能なボリュームを、保持データを破
  棄して撤去する。

## EXIT STATUS

- `0` — ボリュームを切り離した（または短いヘルプを出力した）。
- `1` — ボリュームが見つからない、切り離し不能、またはカーネルが
  切り離しを拒否した。解釈できなかったコマンドラインも `1` で終了
  する。

## ENVIRONMENT

- `LANG` — 短いヘルプに使う優先ロケール（`ja-JP` のような BCP-47
  タグ）。
