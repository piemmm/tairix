## NAME

unmount — マウント済みボリュームの切り離し

## SYNOPSIS

`unmount [option...] name`

## DESCRIPTION

`name` としてマウントされたボリュームを運用から外します。ファイル
システムとデバイスをフラッシュし、`/Storage` 配下のマウントを撤去
し、ボリュームの恒久的な `id::` ルートを取り下げます。`name` は
ボリュームのカタログ名（`usb1`）、マウントされているディレクトリ
（`/Storage/usb1`、または `mount イメージ ディレクトリ` が結び付けた
もの）、またはマウント元のディスクイメージのファイル名
（`Workbench.adf`）で、システム情報 API のマウント一覧とビュー一覧
と照合されます。ほかの利用者のイメージと共通するファイル名は、自分
のイメージを指します。複数のボリュームを指しうるファイル名や、一覧
が先頭しか保持していないファイル名は、どれも指しません。その場合は
マウントされている場所でボリュームを指定してください。
パスは相対でも、末尾がスラッシュでも構いません。`mount` と同じように
解決されます。ほかの利用者の非公開ボリュームは、ファイル名も結び付け
られたディレクトリも一覧に示さないため、`/Storage` でマウントされて
いる場所で指定します。

未確定の書き込みを残したままデバイスが抜かれたボリュームは、
`unavailable-dirty`（または `unavailable-lost`）としてマウント一覧
に残り、通常の `unmount` は拒否します。保持されたデータは検証付き
の再挿入のために保管されています。ファイルがまだ開かれているボリューム、
またはプログラムが作業ディレクトリとしているボリュームに対しても、通常の
`unmount` は拒否します。`--force` は意図的な出口です — ボリューム上でま
だ開かれているファイルは切断され、そこで作業しているプログラムはもう存在
しないディレクトリに取り残され、保持データは破棄されてボリュームは撤去さ
れ、手放したものは監査ログに記録されます。健全なボリュームに対する
`--force` は従来どおりクリーンにフラッシュして切り離します。クリーンな確
定が可能な限り、何も破棄されません。

自分でマウントしたディスクイメージまたはネットワーク共有は、自分で
切り離せます。それ以外のボリュームの切り離しにはマウント権限
（`CAP_FS_MOUNT`）が必要です。カーネルがこれを検査し、すべての判断
を監査します。恒久的なブートボリュームとシステムのビュー結合は
切り離せません。

## OPTIONS

- `-f, --force` — 強制アンマウント：ボリューム上でファイルが開かれている
  間も、プログラムがそこで作業している間も、未確定のデータを確定できない
  場合も、ボリュームを撤去し、開いているファイルを切断して保持データを破
  棄します。
- `-h, -?, --help` — このコマンドの短いヘルプを表示します。

## EXAMPLES

- `unmount usb1` — `usb1` としてマウントされたボリュームをクリーン
  に切り離す。
- `unmount /Storage/usb1` — 同じ操作をマウントポイントで指定。
- `unmount Workbench.adf` — `Workbench.adf` からマウントされた
  ディスクイメージを切り離す。
- `unmount --force usb1` — 利用不能なボリュームを、保持データを破
  棄して撤去する。

## EXIT STATUS

- `0` — ボリュームを切り離した（または短いヘルプを出力した）。
- `1` — コマンドラインを解釈できなかった、または呼び出し元にその
  ボリュームを切り離す権限がない。
- `2` — システム情報サービス、または端末への書き込みが失敗した。
- `32` — ボリュームがマウントされていない、切り離し不能、それを指す
  パスを解決できない、または切り離しに失敗した。

## ENVIRONMENT

- `LANG` — 短いヘルプに使う優先ロケール（`ja-JP` のような BCP-47
  タグ）。
