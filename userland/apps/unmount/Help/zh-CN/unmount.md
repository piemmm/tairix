## NAME

unmount — 分离已挂载的卷

## SYNOPSIS

`unmount [option...] name`

## DESCRIPTION

将挂载在 `name` 下的卷撤出服务：刷写文件系统和设备，撤除
`/Storage` 下的挂载，并收回该卷持久的 `id::` 根。`name` 是卷的
目录名（`usb1`）、挂载它的目录（`/Storage/usb1`，或 `mount 映像 目录`
将其绑定到的目录），或挂载该卷所用磁盘映像的文件名（`Workbench.adf`），
与系统信息 API 的挂载列表和视图列表进行匹配；另一用户的映像与你的映像
同名时，该文件名指的是你自己的映像。可能指多个卷的文件名，或列表只保留
其开头的文件名，不指任何卷：此时请以卷的挂载位置指定它。
路径可以是相对路径，也可以以斜杠结尾：它按 `mount` 的方式解析。其他
用户的私有卷既不列出其文件名，也不列出它所绑定的目录，因此须以它在
`/Storage` 中的挂载位置来指定。

设备在尚有未提交写入时被拔出的卷，会以 `unavailable-dirty` 的状态留在
挂载列表中，普通的 `unmount` 会拒绝：其保留的数据将为经过验证的重新插入
而保存。重新插回后无法证明未被更改的卷（`recovery-conflict`）同样会被
拒绝，该卷仍保存着那些数据；未提交写入无法保留的卷（`unavailable-lost`）
也会被拒绝，以便承认这些写入的丢失，而非略过。对于其上仍有打开的文
件，或被某个程序用作工作目录的卷，普通的 `unmount` 同样会拒
绝。`--force` 是有意的出口 —— 切断该卷上仍然打开的文件，让在其中工作的
程序留在一个已不存在的目录中，丢弃保留数据、撤除该卷，并将所放弃的内容
记入审计日志。对健康的卷，`--force` 仍会干净地刷写并分离；只要可以干净
提交，就不会丢弃任何数据。

你自己挂载的磁盘映像或网络共享，可由你自行分离；其他任何卷都需要
挂载权限（`CAP_FS_MOUNT`）。内核会检查它并审计每个决定。
永久的启动卷和系统的视图绑定不可分离。

## OPTIONS

- `-f, --force` — 强制卸载：即使有文件在该卷上打开、有程序在其中工作，或
  其未提交的数据无法提交，也撤除该卷，切断打开的文件并丢弃保留的数据。
- `-h, -?, --help` — 显示本命令的简短帮助。

## EXAMPLES

- `unmount usb1` — 干净地分离挂载为 `usb1` 的卷。
- `unmount /Storage/usb1` — 同样的操作，以挂载点命名。
- `unmount Workbench.adf` — 分离从 `Workbench.adf` 挂载的磁盘映像。
- `unmount --force usb1` — 撤除不可用的卷并丢弃其保留数据。

## EXIT STATUS

- `0` — 卷已分离（或已输出简短帮助）。
- `1` — 无法理解命令行，或调用者无权分离该卷。
- `2` — 系统信息服务或写入终端失败。
- `32` — 该卷未挂载或不可分离，指定它的路径无法解析，或分离失败。

## ENVIRONMENT

- `LANG` — 简短帮助的首选区域设置（BCP-47 标签，如 `zh-CN`）。
