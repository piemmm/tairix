## NAME

cp — ファイルとディレクトリを複写する

## SYNOPSIS

`cp [-dfHilLnPrRsvT] [--sparse=WHEN] [--preserve=LIST] [--no-preserve=LIST] [-t dir] [--] source... dest`

## DESCRIPTION

各ソースオペランドを宛先へ複写します。ソースが一つで、宛先がディレクトリ
を指さない場合、ソースはその正確なパスへ複写されます。宛先が既存のディレ
クトリを指す場合 — そしてソースが複数あるときは常に — 各ソースはそのディ
レクトリの*中へ*、自身の基底名で複写されます。

ディレクトリのソースは `-r` があるときだけ複写され、部分木全体が再現され
ます。`-r` がなければディレクトリオペランドは拒否されます。既存の宛先
ファイルは既定では上書きされ、`-n` では飛ばされ、`-i` では標準エラースト
リーム上で尋ねられます（断られた質問はその複写を飛ばし、GNU と同じく実行
を失敗とします。読めない返答が同意として扱われることは決してありませ
ん）。ソースのファイルそのもの（同じ名前、その別名、またはそれへのリン
ク）である宛先は、同じファイルとして拒否され、元のまま残されます。ただし
`-l` はそれをすでにリンク済みとみなします。`-f` が既存の名前の場所に置く
リンクは、一度の操作でその場所を占めます。リンクは何かが置き換えられる前
に作られるので、作れなかったリンクは名前をそのまま残します。

読めない、作れない、または書き込めないファイルは報告され、それでも残りは
複写されます。そのファイルのディレクトリの残りも同様です。`--` はオプ
ション解析を終え、以降のすべての引数はパスです。

新しいファイルは、ソースの許可ビットから set-ID ビットとスティッキービッ
トを除き、umask を差し引いたモードで作られるので、非公開のファイルのコ
ピーは非公開のままです。すでに存在する宛先は自身のモードを保ちます。新し
いディレクトリは最終的に、ソースの許可ビットとスティッキービットから
umask を差し引いたモードになります。中へエントリを複写している間は所有者
に開かれているので、ソースディレクトリが読み取り専用でも、umask が所有者
の書き込みを許さなくても、丸ごと複写されます。宛先のツリーの中で出会った
シンボリックリンクを通して書き込むことは決してありません。

GNU の `-a`/`--archive` と、`--preserve=links,xattr` 以外の `--preserve`
の組み合わせは、狭めて受け付けるのではなく**拒否**されます。`-a` は
`-dR --preserve=all` であり、`--preserve=all` にはノードのタイムスタンプ
が含まれますが、このシステムにはそれを設定できる呼び出しがありません。そ
のため `-a` に従うと、行われなかった保持を報告することになります。それ以
外の部分には `-dR` を使ってください。

各コピーは、コピー先が保持できる限り、コピー元の拡張属性（RISC OS のファ
イルタイプ、Mac のタイプとクリエータなど）を引き継ぎ、スパースファイルの
穴を穴のまま保ちます。コピー先が保持できない属性は、実行の終わりに 1 つ
の警告と、標準情報ストリーム上の `omission` レコードで報告されま
す。`--preserve=xattr` を指定すると、そのようなコピーは代わりに失敗しま
す。

ディレクトリがそれ自身の中にコピーされることはありません。ソースの内側に
ある宛先は、リンク、`..`、ボリュームの別名などどのように綴られていても、
何かが書き込まれる前に拒否されます。また、コピー中にソースの中へ移された
ディレクトリに走査が出会うと、そこでコピーは止まります。

## OPTIONS

- `-r, -R, --recursive` — ディレクトリとその中身を複写する。
- `-f, --force` — 宛先ファイルを作れないとき、それを削除して複写を一度だ
  けやり直す。`-l` や `-s` のとき、または `-P` が再現するリンクでは、リ
  ンクを既存の名前の場所に置く。
- `-i, --interactive` — 既存ファイルを上書きする前に尋ねる。`y`/`Y` で始
  まる返答だけが同意で、断られた質問はそのファイルを飛ばし、実行を失敗と
  する。
- `-n, --no-clobber` — 既存ファイルを決して上書きしない。`-i` と `-n` は
  後に書かれた方が勝つ。
- `-l, --link` — 宛先に、バイト列の複写ではなく元のノードの二つめの名前
  を与える。後の書き込みで両者が食い違うことがない。ディレクトリの元には
  引き続き `-r` が必要である。
- `-s, --symbolic-link` — 元を名指すシンボリックリンクを作る。複写はしな
  い。
- `-P, --no-dereference` — ソースのシンボリックリンクはすべて、指す先を
  コピーする代わりに、同じターゲットをそのまま保持するリンクとして再現す
  る（相対リンクや宙に浮いたリンクもコピー後に残る）。
- `-L, --dereference` — ソースのシンボリックリンクをすべてたどり、指す先
  をコピーする。
- `-H` — オペランドとして指定されたシンボリックリンクはたどるが、ツリー
  内で出会うリンクは再現する。`-H`、`-L`、`-P` のいずれもなければ、再帰
  コピーはオペランドのものも含めてすべてのリンクを再現し、それ以外のコピ
  ーはオペランドのリンクをたどる（GNU と同じ）。`-l` はたどったリンクが
  指す先をリンクする。
- `--preserve=links` — 同じノードを名指す二つの元は、宛先で二つの複写で
  はなく二つの名前になる。複写が容量を黙って二倍にすることがない。
- `--preserve=xattr` — すべての拡張属性を引き継がなければならない。コ
  ピー先がそのいずれかを保持できないコピーは、その属性を名指して失敗す
  る。`--preserve=links,xattr` は両方を求める。
- `--no-preserve=xattr` — 拡張属性を一切コピーしない。`ownership` と
  `timestamps` も受け付けるが、これらはもともと保持されない。
- `--no-preserve=mode` — 新しいファイルとディレクトリを、ソースのモード
  ではなく、何も指定がないときに新しいものが取るモードから umask を差し
  引いたモードで作る。`--no-preserve=all` も同じことをする。
- `--sparse=WHEN` — スパースファイルのコピー方法。既定の `auto` は穴を保
  つ。`always` はさらに、格納されているゼロのブロックをすべて書き込まず
  に残す。`never` はすべてのバイトを書き込む。
- `-d` — GNU の道具と同じく、`-P` と `--preserve=links` を合わせたもの。
- `-v, --verbose` — 各複写を `'source' -> 'dest'` の形で報告する。
- `-t dir, --target-directory=dir` — すべてのソースを `dir` へ複写する。
  これは既存のディレクトリでなければならない。値は密着形
  （`-tdir`、`--target-directory=dir`）または次の引数として与える。
- `-T, --no-target-directory` — 宛先を普通のファイルとして扱う。許される
  ソースはちょうど一つ。`-t` とは組み合わせられない。
- `-h, -?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `cp notes.txt backup.txt` — ファイルを新しい名前へ複写する。
- `cp -r Projects Archive` — `Projects` の木を `Archive` の中に再現する
  （存在しなければ `Archive` として）。
- `cp -v -t Backup a.txt b.txt` — 両ファイルを `Backup` へ複写し、各複写
  を報告する。

## EXIT STATUS

- `0` — すべての複写が成功した（`-n` による飛ばしは失敗ではない）。
- `1` — 複写できないファイルがあった、`-i` の質問が断られた、または問い
  かけか出力が失敗した。各失敗の理由は標準エラーに印字される。解釈できな
  かったコマンド行も `1` で終了する。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`ja-JP` のような BCP-47 タグ）。
