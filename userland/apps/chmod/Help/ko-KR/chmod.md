## NAME

chmod — 파일 모드 비트 변경

## SYNOPSIS

`chmod [-cfRv] [--] MODE file...`

## DESCRIPTION

각 파일 피연산자의 허가 비트를 순서대로 `MODE`로 변경합니다. `MODE`는
허가 비트를 통째로 바꾸는 절대 8진수 값(`644`, `0755` 등)이거나, 파일의
현재 비트를 변형하는 쉼표로 구분된 기호 절
`[ugoa]*([-+=]([rwxXst]*|[ugo]))+` 또는 `[-+=][0-7]+`(`g+w`, `o-rx`,
`a=rx`, `u+s`, `g=u`, `=644`)의 목록입니다. 기호 `X`는 디렉터리이거나
이미 실행 비트를 가진 파일에만 실행 권한을 부여하고, `g=u`는 그룹에
소유자의 비트를 주며, `s`는 소유자와 그룹의 set-ID 비트를 설정하고,
`t`는 스티키 비트를 설정합니다. 아무도 지정하지 않는 절(`+x`, `=r`)은
umask가 가진 비트를 제외한 모든 필드를 변경합니다.

디렉터리에서는 모드가 set-user-ID와 set-group-ID 비트를 지정하지 않는 한
두 비트가 그대로 유지됩니다. 지정하는 방법은 `s`(`g-s`), 연산자 뒤의
8진수(`=755`), 또는 다섯 자리 이상의 8진수 값(`00755`)입니다. 디렉터리의
새 항목에 그 디렉터리의 그룹을 주는 것이 디렉터리의 set-group-ID
비트이므로, `chmod 755`는 이 비트를 유지합니다.

파일의 모드는 소유자만 변경할 수 있습니다. 커널은 그 외 누구도
거부하며, capability를 보유해도 예외가 되지 않습니다. 피연산자로
지정한 심볼릭 링크의 경우 그 링크가 가리키는 파일이 변경됩니다.
`-R`을 주면 디렉터리 피연산자를 변경한 뒤 그 내용을 재귀적으로
변경하며, 트리 안에서 만나는 심볼릭 링크는 건드리지 않고 그것이
가리키는 대상도 건드리지 않습니다. 도달하거나 변경할 수 없는 파일은
보고되고, 나머지는 그래도 변경됩니다. `--`는 옵션 해석을 끝내며,
이후의 모든 인수는 피연산자입니다. `-`로 시작하는 모드는 대시 없이
쓰거나(`a-w`) 옵션을 먼저 끝내십시오(`chmod -- -w file`).

## OPTIONS

- `-R, --recursive` — 파일과 디렉터리를 재귀적으로 변경합니다.
- `-c, --changes` — 모드가 실제로 바뀐 파일만 보고합니다.
- `-v, --verbose` — 변경이 거부되었거나 도달할 수 없었던 파일을
  포함해 처리한 모든 파일을 보고합니다.
- `-f, --silent, --quiet` — 대부분의 오류 메시지를 숨깁니다.
  실행은 여전히 실패하며 종료 코드가 이를 보고합니다.
- `--preserve-root` — `-R`과 함께, 어떻게 도달하든 `/` 변경을
  거부합니다.
- `--no-preserve-root` — `/`를 다른 디렉터리와 똑같이 다룹니다(기본값).
- `-h, -?, --help` — 이 명령의 짧은 도움말을 표시합니다.

## EXAMPLES

- `chmod 644 notes.txt` — 소유자는 읽기/쓰기, 나머지는 읽기 전용.
- `chmod g+w shared.txt` — 현재 비트에 그룹 쓰기를 추가.
- `chmod -R a=rx Docs` — `Docs` 트리를 모두가 읽고 탐색할 수 있게
  만듭니다.
- `chmod +x build.sh` — 스크립트를 umask가 허용하는 모든 사용자가 실행할
  수 있게 만듭니다.

## EXIT STATUS

- `0` — 모든 모드 변경이 성공했습니다.
- `1` — 도달하거나 변경할 수 없는 파일이 있었거나 출력이
  실패했습니다. 각 이유는 표준 오류로 출력됩니다(`-f`에서는 숨김).
  이해하지 못한 명령줄이나, 모드 피연산자가 8진수도 기호도 아니었던
  명령줄도 `1`로 끝납니다.

## ENVIRONMENT

- `LANG` — 짧은 도움말에 사용할 선호 로캘(`ko-KR` 같은 BCP-47
  태그).
