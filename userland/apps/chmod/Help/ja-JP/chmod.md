## NAME

chmod — ファイルのモードビットを変更する

## SYNOPSIS

`chmod [-cfRv] [--] MODE file...`

## DESCRIPTION

各ファイルオペランドの許可ビットを順に `MODE` へ変更します。`MODE` は、
許可ビットを丸ごと置き換える絶対 8 進値（`644`、`0755` など）か、ファイ
ルの現在のビットを変換するコンマ区切りのシンボリック節
`[ugoa]*([-+=]([rwxXst]*|[ugo]))+` または
`[-+=][0-7]+`（`g+w`、`o-rx`、`a=rx`、`u+s`、`g=u`、`=644`）のいずれかで
す。シンボリックの `X` は、ディレクトリか、すでに実行ビットを持つファイ
ルにのみ実行を与えます。`g=u` はグループに所有者のビットを与え、`s` は所
有者とグループの set-ID ビットを設定し、`t` はスティッキービットを設定し
ます。対象を指定しない節（`+x`、`=r`）は、umask に含まれるビットを除い
て、すべてのフィールドを変更します。

ディレクトリでは、set-user-ID ビットと set-group-ID ビットは、モードがそ
れらを指定しない限りそのまま保たれます。指定するには、`s` を使う
（`g-s`）か、演算子の後に 8 進数を書く（`=755`）か、5 桁以上の 8 進値を
使います（`00755`）。新しいエントリにディレクトリのグループを与えるのは
ディレクトリの set-group-ID ビットなので、`chmod 755` ではこのビットが保
たれます。

ファイルのモードを変更できるのは所有者だけです。カーネルはそれ以外
の全員を拒否し、capability を保持していても例外にはなりません。
オペランドとしてシンボリックリンクを指定すると、それが指すファイル
が変更されます。`-R` を付けるとディレクトリオペランドを変更した後、
その内容を再帰的に変更します。ツリーの中で出会ったシンボリックリン
クには手を付けず、それが指すものにも手を付けません。到達または変更
できないファイルは報告され、それでも残りは変更されま
す。`--` はオプション解析を終了し、以降の引数はすべてオペランドで
す。`-` で始まるモードは、ダッシュなしで書く（`a-w`）か、先にオプ
ションを終了してください（`chmod -- -w file`）。

## OPTIONS

- `-R, --recursive` — ファイルとディレクトリを再帰的に変更する。
- `-c, --changes` — モードが実際に変わったファイルだけを報告する。
- `-v, --verbose` — 処理したすべてのファイルを、変更が拒否されたも
  のや到達できなかったものも含めて報告する。
- `-f, --silent, --quiet` — ほとんどのエラーメッセージを抑止する。
  実行は失敗のままで、終了コードがそれを報告する。
- `--preserve-root` — `-R` のとき、どのようにたどり着いても `/` の変更を
  拒む。
- `--no-preserve-root` — `/` をほかのディレクトリと同じように扱う（既
  定）。
- `-h, -?, --help` — このコマンドの短いヘルプを表示する。

## EXAMPLES

- `chmod 644 notes.txt` — 所有者は読み書き、他は読み取りのみ。
- `chmod g+w shared.txt` — 現在のビットにグループの書き込みを追加。
- `chmod -R a=rx Docs` — `Docs` ツリーを全員が読めて辿れるように
  する。
- `chmod +x build.sh` — スクリプトを、umask が許すすべての人が実行できる
  ようにする。

## EXIT STATUS

- `0` — すべてのモード変更が成功した。
- `1` — 到達または変更できないファイルがあった、あるいは出力が失敗
  した。それぞれの理由は標準エラーに出力される（`-f` では抑止）。解
  釈できなかったコマンド行も、モードオペランドが 8 進でもシンボリッ
  クでもなかったコマンド行も `1` で終了する。

## ENVIRONMENT

- `LANG` — 短いヘルプに使う優先ロケール（`ja-JP` のような BCP-47
  タグ）。
