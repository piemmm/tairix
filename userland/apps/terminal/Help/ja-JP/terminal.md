## NAME

terminal — グラフィカルな端末エミュレーター

## SYNOPSIS

`terminal`

## DESCRIPTION

80×25 文字の画面上でユーザーの既定シェルをホストするデスクトップ
ウィンドウを開きます。フォーカスされたウィンドウに打鍵されたキーは
シェルへ送られ、シェルが書き出すすべて（標準出力も標準エラーも）は
共有の ANSI/VT 語彙で解釈され、設定で選ばれたカラースキームで描画
されます。端末自体は決してエコーしません。エコーと行編集はコンソール
上と同じくシェルのものです。

ウィンドウは、有効なテキストサイズでの 80×25 画面の寸法で開くため、
表示されるディスプレイに収まります。そのサイズに対してディスプレイが
小さすぎる場合は、画面を狭めるのではなくテキストを縮小します。これは、
80 列用にレイアウトを行うプログラムが、引き続きそれらを必要とする
ためです。

端末はデスクトップのプログラムライブラリ（タスクバーの `Library`
ボタン）から、またはシェルから名前で起動します。実行中のグラフィカル
セッションが必要です。それがなければウィンドウチャネルに到達できず、
端末は標準エラーストリームに拒否を報告して終了します。

シェルが終了する（例えば `exit`）か、デスクトップからウィンドウを閉
じるとセッションは終わります。ウィンドウを閉じると、シェルの入力に
ファイル終端が届いてシェルは終了します。

最後のウィンドウを閉じても端末は終了しません。アイコンはデスクトップの
アイコンバーに残り、それをクリックすると新しいウィンドウが開きます。
そのアイコンのメニューの *終了* は、すべてのウィンドウを閉じてプログラム
を終了します。

画面の上端からスクロールして消えた行は、*設定…* で変更しない限り
直近の 500 行が保持され、マウスホイールでさかのぼってスクロールでき
ます。`Shift Page Up` と
`Shift Page Down` は 1 画面ずつ移動し、`Shift Home` は最も古い行
へ、`Shift End` は画面へ戻ります。さかのぼって表示している間に届いた
出力は表示位置を動かさず、キーを入力すると表示は画面へ戻ります。
ウィンドウのサイズを変えると、行は切り捨てられずに新しい幅で折り返し直
され、全画面プログラム自身の画面では行は保持されません。メモリが不足す
ると、最も古い行から先に解放されます。

画面上の任意の場所で副（右）マウスボタンを押すと、端末のメニューが
開きます。*スクロールバックを消去* 以外のすべての行には、メニューが開いて
いるかどうかに関わらず動作するキーボードショートカットがあり、`Escape` を
押すかメニューの外をクリックすると、何も選択せずにメニューを閉じます。

| 行 | ショートカット | 動作 |
| --- | --- | --- |
| 設定… | `Ctrl ,` | 下記の設定を開きます。 |
| テキストを大きく | `Ctrl +` | 画面を一段階大きく描画します。 |
| テキストを小さく | `Ctrl -` | 画面を一段階小さく描画します。 |
| 実際のサイズ | `Ctrl 0` | 既定のテキストサイズに戻ります。 |
| 画面を消去 | `Ctrl Shift K` | シェルに書き込むことなく画面を消去します。表示されていた内容には、引き続きスクロールで戻れます。 |
| スクロールバックを消去 | — | 画面の上に保持されている行を破棄します。 |
| 閉じる | `Ctrl Shift W` | ウィンドウを閉じ、シェルを終了します。 |

設定は専用のウィンドウで開き、端末で作業している間も開いたままにして
おけます。*設定…* をもう一度選ぶと、そのウィンドウが前面に出ます。2 つの
タブがあり、その上でホイールを回すとスクロールします。*完了*、`Escape`、
またはウィンドウの閉じるボタンで閉じます。**外観** では、
カラースキームの選択、テキストサイズとスクロールバックに保持する行数
（0 行から 10,000 行まで、最初は 500 行）の設定、およびユーザー独自の
スキームの編集を行います。同梱されているスキームは *System*
（デスクトップのダークまたはライトの外観に従います）、*Midnight*、
*Phosphor*、*Amber*、*Ember*、*Contrast*、*Paper*、および *Custom*
です。*Custom* を選択すると、選択ツールの下で編集された色が使用され
ます。これは背景、前景、カーソル、カーソルテキスト、および 16 個の
ANSI カラーという、画面を構成する 20 色のグリッドで、選択されている
色にはカラーピッカーがあります。ピッカーは色相・彩度・明度、赤・緑・青、
または 16 進表記で色を設定し、選択したときの色を横に表示します。それを
クリックすると元の色に戻ります。

**エフェクト** では、画面の描画方法を設定します。新しい端末は不透明度 80 %、
背景のぼかしは半分の強さ、そのほかのエフェクトはすべてオフの状態で開くため、
デスクトップはくっきり透けて見えるのではなく、テキストの背後にすりガラスの
ように見えます。

| エフェクト | 動作 |
| --- | --- |
| 不透明度 | 背景の固形度。最大未満では、テキストの背後にデスクトップが透けて見えますが、テキストの可読性は完全に維持されます。 |
| 背景のぼかし | 透過ウィンドウの背後のデスクトップをどの程度ぼかすか。完全に不透明なウィンドウには影響しません。 |
| スキャンライン | 一行おきに暗くします。シャドウマスクの外観の平坦な部分です。 |
| グロー | 明るいピクセルの光を周囲に広げ、強く駆動されたブラウン管のような柔らかい光のにじみをテキストにまとわせます。 |
| ノイズ | アナログ信号にあるような、ピクセルごとの動的なノイズフロアです。 |
| 蓄光 | 点灯したピクセルがどのくらい持続するか。高速にスクロールするテキストが残像を残すようになります。 |
| 揺らぎ | 同期が外れたブラウン管のような、ゆっくりとした水平方向の揺れです。 |

すべての変更は即座に反映され、ユーザー自身のプロファイルに保存される
ため、後で開く端末も同じ状態で開きます。プロファイルはオペレーティング
システムの設定サービスが保持し、この端末専用です。ほかのアプリケーション
が読み取ることも変更することもできません。保存されるのはユーザーが実際に
変更した項目だけなので、「既定値に戻す」は現在の値を固定するのではなく
それらの選択を取り除きます。以後は管理者や新しい版の端末が変更した値が
適用されます。端末が解釈できない設定はその既定値のまま残り、標準エラー
ストリームに報告されます。設定サービスに到達できない場合、端末は同梱の
値で動作し、これも報告されます。

## EXIT STATUS

正常に閉じたかシェル自身が終了した後はゼロ。シェルをホストできな
かった場合や、ウィンドウチャネル・共有フレーム領域・イベントメール
ボックスが拒否された場合は非ゼロ（理由は標準エラーストリームに示さ
れます）。

## ENVIRONMENT

`HOME`
: アカウントのホームディレクトリで、端末はここでプロファイルを読み
書きします。これがない場合、端末は既定のプロファイルで動作し、何も
保存しません。

`TERM`
: ホストするシェルへ `xterm-256color` として渡され、この端末が提示
するエミュレーターを表します。継承された値は置き換えられ、環境のその
他の部分はそのままシェルへ引き継がれます。
